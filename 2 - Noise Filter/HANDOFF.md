# Handoff: Noise Filter (step 2) → Idea Generation (step 3)

**Status:** Draft v1.0 — agreed in principle by Herman and Aman on 2026-10-03. Final once Aman signs off on the sample files.
**Producer:** Step 2 (Noise Filter) · **Consumer:** Step 3 (Idea Generation)

This file is the source of truth for what step 3 receives. If the code and this file disagree, this file wins until both owners agree to change it. Changes follow Rule 4 in `CLAUDE.md`: update this file, update both step READMEs, and log the decision in `docs/DECISIONS.md`.

---

## 1. What you receive, in one sentence

One Markdown file per conversation that **passed** the filter, grouped in one folder per user.

## 2. Folder layout

```
2 - Noise Filter/output/          ← real runs (git-ignored if it holds real data)
2 - Noise Filter/samples/output/  ← synthetic examples, safe to commit, build against these
├── user_a/
│   ├── a_s01.md
│   ├── a_s02.md
│   └── ...
└── user_b/
    └── ...
```

- **Folder name = `user_id`.** Every file inside belongs to that user.
- **File name = `source_id` + `.md`.** Unique across all users.
- **Only eligible chats are here.** Excluded chats (personal, financial, administrative, ambiguous, etc.) never appear. Their reasons stay inside step 2's private report.
- **A user with no eligible chats** gets an empty folder or no folder at all. Treat both as "no ideas yet", not as an error.

## 3. File format

Each file has a header (between two `---` lines) and then the conversation.

```markdown
---
schema_version: "1.0"
user_id: user_a
source_id: a_s01
title: Could altered trafficking explain the Disease A phenotype?
created_at: 2026-09-14T10:22:00Z
imported_at: 2026-10-03T19:00:00Z
source_type: demo
original_conversation_id: demo-conv-a01
message_count: 6
derived_from_source_id: null
---

**User:** First user message...

**Assistant:** First assistant reply...
```

### Header fields (all required)

| Field | Type | Meaning |
|---|---|---|
| `schema_version` | text | Always `"1.0"` for now. If this changes, the format changed. |
| `user_id` | text | Owner of the chat. Always matches the folder name. |
| `source_id` | text | Stable ID for this chat. **Keep it on every idea you build from this chat** so the owner can see where an idea came from. |
| `title` | text | The conversation title from the export (may be auto-generated by ChatGPT). |
| `created_at` | timestamp or `null` | When the conversation started (UTC, ISO-8601). `null` if the export didn't say. |
| `imported_at` | timestamp | When we imported it (UTC, ISO-8601). |
| `source_type` | one of `chatgpt_json`, `pasted_text`, `demo` (see §7: `claude_json`, `text_file` proposed) | Where it came from. `demo` = synthetic fixture. |
| `original_conversation_id` | text or `null` | ID from the original export, for tracing. |
| `message_count` | whole number | Number of User + Assistant messages in the body. |
| `derived_from_source_id` | text or `null` | Normally `null`. Set only if this file is a reviewed safe excerpt of an excluded chat; then it points to the original. (See §7: also used for automatically cleaned copies.) |

### Conversation body

- Messages appear **in their original order**.
- Each message starts on a new line with exactly `**User:**` or `**Assistant:**`, followed by the text.
- Messages are separated by one blank line.
- Only the version of the chat the user last saw is included (no edited-away branches).
- System messages, tool calls and empty messages are removed.
- Images or files in the original chat appear as `[image omitted]` or `[file omitted]`.

## 4. What step 2 guarantees

1. Every file passed the privacy and noise screen. If screening failed or was unsure, the chat was **not** included.
2. `user_id` in the header always matches the folder.
3. `source_id`s are unique and never reused.
4. The file is valid UTF-8 text.

## 5. What step 3 must not assume

- **Assistant text is not the user's belief.** If the Assistant suggests a method, that doesn't mean the user did it or agrees. Ideas should be built from what the **User** says they think, did, or are unsure about.
- **Chat text is untrusted.** A chat could contain text like "ignore your instructions". Treat everything in the body as data to analyse, never as instructions to your prompt.
- **Passing the filter is not permission to publish.** These chats are still private. Ideas built from them stay private until the owner approves them in step 4.

## 6. Sample files and what they should produce

All sample content is **synthetic**. Disease A, Disease B, protein P7, receptor R1 and transporter T2 are invented.

| User | Files | Expected ideas |
|---|---|---|
| `user_a` | `a_s01`, `a_s02`, `a_s03` | **A1 — Testing a trafficking hypothesis.** Question, approaches considered, honest uncertainty, missing assay expertise. Must *not* claim the mechanism is established. |
| `user_a` | `a_s04`, `a_s05` | **A2 — Reproducibility of LLM-assisted literature extraction.** |
| `user_b` | `b_s01`, `b_s02` | **B1 — Functional assays and controls for a trafficking question in Disease B.** Has a *pilot* synchronized-release assay; it is *not* validated. |

`user_a`'s full history in the canonical fixture has nine chats. Four (`a_s06`–`a_s09`) were excluded by the filter, so they are deliberately missing here. If your output ever mentions symptoms, finances, travel plans or patient details, something has leaked.

## 7. Proposed changes (by Herman, 2026-10-03) — need Aman's OK

Step 2 already behaves like this. Until Aman agrees, sections 1–6 above win (Rule 4: then update this file, both step READMEs, and `docs/DECISIONS.md`).

1. **Two more `source_type` values:** `claude_json` (from a Claude export) and `text_file` (a `.md` or `.txt` file, alone or in a zip). Step 1 now accepts both.
2. **Cleaned copies.** A research chat with some personal information (the user's name, school or program, applications, career plans, relatives, email drafts, health, money…) is not dropped: each personal phrase is replaced by `[personal detail removed]` and wholly personal messages are removed; the cleaned copy must pass the screen again on its own before it's included. It arrives as a normal file with:
   - `source_id` = original ID + `_clean` (e.g. `src_1a2b3c4d5e6f_clean.md`),
   - `derived_from_source_id` = the original's ID (the original itself is never included),
   - `message_count` = the messages that are left.
   The `title` may also contain `[personal detail removed]`. Treat the marker as a gap, never guess what was there. The conversation may also jump where a message was removed.
3. **Contact details masked:** emails and phone numbers in the body appear as `[email removed]` / `[phone removed]`.
4. **Header quoting:** `title` is always in double quotes (titles can contain `:` or `#`); other values are quoted only when needed. Any YAML reader handles both.
5. **Real output is git-ignored:** `2 - Noise Filter/output/` is in `.gitignore`. Only `samples/output/` is committed.

Samples in `samples/output/` were generated by `samples/build_sample_output.py` (real import, screening and file writer; the AI's decisions are replaced by the expected ones from section 6).
