**User:** I've been reviewing a lot of manuscripts lately and it bothers me that nobody actually runs the analysis code. I think peer reviewers should be expected to check the code and data, at least to the point of re-running the main figure. Is there any precedent for journals building reproducibility checks into the review stage itself rather than leaving it to post-publication?

**Assistant:** There is some precedent. A few journals in economics, political science and computational fields employ data editors who re-run submitted replication packages before acceptance. Others ask reviewers to tick a checklist about code availability without requiring execution. The models differ in who does the work: volunteer reviewers, paid staff, or a dedicated reproducibility reviewer added to the panel. The main barriers reported are time cost, environment setup, and confidential or very large datasets. A staged approach, where a light check (does the code run, does it produce the headline numbers) is mandatory and a deep audit is optional, tends to be the most realistic starting point.

**User:** That staged idea makes sense. Related thing I keep noticing while doing literature reviews: the papers with clean positive results get cited constantly, while careful null results on the same question just sit there with two or three citations. I suspect citation bias toward positive findings is distorting what the field thinks is settled. How would I actually measure that rather than just complaining about it?

**Assistant:** A common design is to assemble a set of studies addressing the same question, code each one as supportive or null based on its primary outcome, and then model citation counts while controlling for journal, publication year, sample size and author team size. Citation network analysis adds another layer: you can check whether later reviews and meta-analyses disproportionately cite the positive studies. Negative binomial regression is typical for count data. The tricky parts are coding the direction of results reliably, ideally with two independent coders, and handling the fact that positive studies may also be larger or better designed, which you'd want to adjust for.

**User:** I like the two-coder approach. I think I'll start with one well-defined question where there are maybe forty studies, so I can do it by hand before trying to automate any of it. Honestly both of these problems feel connected to me: if reviewers checked code, fewer shaky positive results would get through, and the citation skew would have less to feed on.

**Assistant:** That's a reasonable framing and a manageable pilot. Forty studies is enough to see a pattern and small enough to code carefully. You might pre-register the coding rules and the regression model before collecting citation counts so the analysis can't drift toward the answer you expect. If you later want to link it to the reproducibility point, you could note which of those forty studies shared code and whether that is associated with citation rate, though causal claims would be hard to support.
