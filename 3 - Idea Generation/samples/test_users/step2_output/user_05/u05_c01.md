**User:** I'm setting up a regression discontinuity project on class size. The district data I have uses a maximum class size of 30, so when a grade cohort hits 31 students the school has to split into two classes and average class size drops sharply. I want to use enrolment as the running variable and estimate the effect on end-of-year test scores. I know the basic fuzzy RD setup, but I'm wondering how people usually handle multiple cutoffs at 30, 60, 90 in one model.

**Assistant:** With multiple cutoffs, the common approaches are either to normalise the running variable relative to the nearest threshold and pool, or to estimate each cutoff separately and then combine. Pooling gains power but assumes the effect is similar at each cutoff, which may not hold since going from 30 to 15.5 students is a much bigger proportional change than going from 90 to 22.5. A useful middle ground is to use predicted class size from the cap rule as the instrument for actual class size, which naturally scales the first stage at each cutoff. You can then check heterogeneity by estimating cutoff-specific local effects and seeing whether they line up.

**User:** That makes sense. I'm leaning toward the predicted class size instrument, since the first stage is going to be fuzzy anyway. Some schools split early at 28 or 29, and some ask for exemptions and run a class of 32. My plan is to use local linear regression with a triangular kernel and MSE-optimal bandwidths, and cluster at the school level. Does clustering by school make sense when the variation is at the grade-cohort level?

**Assistant:** Clustering at the school level is usually the safer choice. Cohorts within the same school share teachers, administrators, and policies on splitting classes, so their errors are probably correlated. Clustering only at the grade-cohort level could understate your standard errors. If you have few schools, think about wild cluster bootstrap. Also, with a discrete running variable like enrolment counts, it is worth checking robustness to the discreteness, for example by looking at how sensitive estimates are to bandwidth choice and reporting results across a range of bandwidths, not just the optimal one.
