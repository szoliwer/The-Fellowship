**User:** Someone suggested prototypical networks for our fish call problem. As I understand it, you learn an embedding and classify by distance to the average embedding of a few examples per class. We have a few call types with only 10 to 20 labelled examples. Would that work, and would it handle calls we haven't labelled yet? A lot of the sounds on our reefs we can't even attribute to a species.

**Assistant:** Prototypical networks are a good fit for classes with very few examples, because they only need enough examples to estimate a class centre in embedding space. The quality depends heavily on the embedding, which is usually trained episodically on many other classes or derived from a pretrained model. For unknown sounds, you can add an open-set threshold: if a clip is far from all prototypes, flag it as unknown rather than forcing a label. Clustering the unknowns afterwards can surface recurring unidentified call types worth investigating.

**User:** Flagging unknowns and clustering them is exactly what I'd want ecologically, because the unknown calls might be the interesting ones. But I'll be honest, I can follow the concept and still have no idea how to implement episodic training. This is the piece of the project where I really need a machine learning person working alongside us, not just a tutorial.

**Assistant:** That's a fair assessment. Episodic training, evaluation design and open-set thresholds involve a lot of practical choices that are easy to get wrong without experience. A collaborator could set up the pipeline while you define the call taxonomy and validate outputs. In the meantime, you can prepare by standardising your labelled clips, writing short descriptions of each call type, and setting aside a held-out test set from sites not used for training.
