**User:** My BibTeX file is a mess from copying entries out of different sources. Some keys are AuthorYear, some are random strings, some titles are in all caps, and the page ranges use single hyphens. Can you give me a consistent set of rules and maybe a quick way to apply them?

**Assistant:** Suggested rules: keys as firstauthorlastnameYEARfirstword, all lowercase; titles in sentence or title case with braces protecting acronyms and proper nouns, like {ARG} or {DNA}; page ranges with a double hyphen; journal names in full or consistently abbreviated; drop fields like abstract, file and keywords. For automation, a tool such as bibtex-tidy can reformat fields, sort entries and remove duplicates, and many reference managers can regenerate citation keys with a pattern you specify.

**User:** If I regenerate the citation keys, won't all my cite commands in the manuscript break? The document has around ninety citations spread across six chapter files, and I really don't want to hunt through them by hand. Is there a safe way to rename the keys and update the document at the same time, or should I just leave the keys alone this close to submission?

**Assistant:** Regenerating keys would break existing cite commands unless you update them too. One way is to export a mapping of old keys to new keys before regenerating, then run a short script that reads the mapping and does find-and-replace across all six .tex files. That works, but it adds risk close to a deadline. The safer option is to keep the current keys and only tidy the fields: titles, page ranges, journal names and removed clutter. Afterward, compile once and skim the reference list in the PDF for lowercased acronyms or missing years, the most common leftovers.
